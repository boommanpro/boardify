# 工程实施规范

## 栈与依赖门禁

1. 检查依赖清单和锁文件，沿用已有包管理器、框架、路由、目录、格式与测试约定；禁止为套模板重建现有项目。
2. 新项目按 SKILL.md 使用 assets/starter 中的 React、Vite、TypeScript、shadcn/ui 与 ECharts 起始工程，不从零重写基础设施。已有项目仅选择性迁移适配后的组件，保留原有配置与用户修改。
3. 安装前核查运行时版本、框架兼容性、依赖来源和许可；锁定最终依赖。不得在可复现交付命令中依赖浮动 latest。
4. shadcn 按目标项目版本与原语方案接入，只添加实际需要的组件。不要盲目运行初始化覆盖主题、别名或 components.json。
5. 不因参考图谱推荐而引入第二套完整 UI 库或第二套图表引擎；确需混用，先记录体积、交互一致性和维护代价。

## 建议目录结构

starter 已按下列分层组织，新工程沿用而不重排。已有项目保留原结构，只按职责分离原则迁移：

```text
src/
├── components/
│   ├── ui/            # shadcn 生成组件
│   ├── chart.tsx      # 统一 ECharts 容器（尺寸观察/事件/销毁）
│   ├── region-map.tsx # 地图下钻组件（或按项目命名）
│   └── layout/        # 页头、筛选栏、面包屑（有需要时）
├── lib/               # echarts 注册入口、图表配置、地图/工具函数
├── data/              # 数据层：唯一数据出口；mock 与真实接口同构可切换
│   └── maps/          # 地图清单与（本地资源在 public/ 下）
├── hooks/             # 主题、尺寸等共享逻辑
├── test/              # 单元测试
├── App.tsx / main.tsx / index.css
public/maps/           # 本地 GeoJSON（fetch-maps.mjs 下载，运行时禁止外网）
```

- 数据层是唯一数据出口：页面与组件不从数据层之外散落 fetch，不硬编码数据数组；mock 与真实 API 用同一形状，接真实数据时一处切换。
- 一个图表 = 一个配置工厂 + 一处使用；组件保持小，命名 `buildXxxOption`、`XxxPage`、`XxxCard`。
- mock 数据必须“像真的”：中文标签、合理数量级、有趋势和波动，不用 `test1 / 111`。

## 职责分离

| 层 | 负责 | 禁止 |
| --- | --- | --- |
| 页面与布局 | 路由、信息层级、筛选编排 | 内嵌接口密钥、巨量地图数据 |
| 通用界面组件 | 表单、对话框、表格、状态展示 | 私自改变业务指标口径 |
| 数据访问 | 请求、取消、错误归类、权限边界 | 将失败静默转换为成功空数组 |
| 领域转换 | 字段校验、聚合、格式化、行政区关联 | 修改传入数据造成跨图表污染 |
| 图表适配 | 实例生命周期、配置生成、主题转换 | 每次渲染重新创建实例 |
| 地图资产管理 | 本地清单、校验、按层加载、版本缓存 | 任意拼接外部地图地址 |

按现有目录实现这些职责，不为满足表格机械创建空目录。组件以明确类型传入数据和回调；跨模块共享状态只保存必要的筛选、选择与导航，不保存可从数据推导的重复副本。

## 请求与状态

- 校验接口响应的必需字段、数值范围和时间格式；不可信 HTML 不得进入提示框、标签或富文本。
- 筛选切换使用请求取消或递增请求标识，旧响应不得覆盖新状态。卸载后不得继续写入状态。
- 首次加载显示骨架或明确进度；刷新保留旧数据时标注“正在更新”及数据时间；失败展示可理解原因和重试入口。
- 错误至少区分网络、超时、权限、服务端、数据结构和资源不存在；禁止自动无限重试。
- 以确定性样本覆盖空集合、零、负数、极值、长名称、重复区域码和缺失字段。

## 生命周期与性能

- 图表仅在客户端且容器尺寸有效时初始化；服务端渲染项目必须隔离浏览器 API。
- 卸载时释放实例、事件、观察器、定时器和未完成请求；开发模式重复挂载不得产生重复事件。
- 按需加载页面、图表模块和地图层级。按需引入 ECharts 时显式注册渲染器；不能只导入 echarts/core 后直接使用任意图表。
- 对表格大数据先确定分页或虚拟化策略；对大图表先确定聚合、采样和缩放策略，不得以抽样掩盖业务极值。
- 在约定设备、浏览器、数据量和视口下测量首屏、交互、资源体积及持续更新表现；记录测量方法，禁止虚构性能结果。

## 安全与部署

- 前端环境变量不能保存服务端秘密；地图服务密钥按供应商方案限制来源与权限，秘密类凭据放服务端。
- 授权在服务端实施，隐藏按钮不能替代鉴权。日志、截图、导出和网络证据必须脱敏。
- 导出 CSV 时处理公式注入；文件名、筛选参数和地图资源路径必须校验，禁止任意路径读取。
- 离线交付不得依赖外部字体、图标、CDN 脚本或在线地图。构建部署后验证资源基础路径与直接刷新路由。
- 使用锁文件对应的冻结安装流程。只运行项目实际存在的检查脚本；缺失脚本必须说明或经授权补充，不能把未执行写成通过。

## 最低检查集

依次执行类型检查、静态检查、领域转换与状态测试、生产构建、生产产物启动、浏览器关键路径验证。每步保存实际命令、工作目录、退出码和日志索引，并关联 delivery-validation.md 门禁。编译通过不代表运行正常。

starter 提供 npm test、npm run build 和 npm run preview；build 包含 TypeScript 检查，未提供独立 lint 命令。需要静态规范检查时补充配置并实际执行，不得声称不存在的检查已通过。交付源码、锁文件、静态构建产物及运行说明，通过静态服务器运行，不承诺双击 HTML。
