# 设计系统与信息表达

## 选择依据

将前端设计图谱作为候选索引，不把流行度当作选型结论。先依据用户任务、信息密度、已有框架和组件复杂度选择一套主语言。已有设计系统优先复用；新看板默认建议克制的中性底色、清晰分隔与少量强调色，不默认霓虹大屏或玻璃拟态。

调研图谱描述了极简、企业中台、Material、Fluent、玻璃拟态等风格。这里采纳其“分开比较组件生态与视觉风格”的方法，不照抄整页卡片布局，不将趋势描述作为客观排名。

## 视觉契约

实施前记录主风格、颜色角色、字体、间距、圆角、阴影、密度、图表调色板和响应策略。以下为无品牌约束时的建议起点，确定后全局一致使用。

| 项目 | 建议起点 | 必须检查 |
| --- | --- | --- |
| 布局 | 页面标题与筛选、核心指标、主分析区、明细区 | 首屏能识别业务问题和当前范围 |
| 间距 | 4、8、12、16、24、32 像素档位 | 相同层级不出现随机间距 |
| 字号 | 正文 14–16、辅助 12–14、标题 20–28 像素 | 不靠缩小文字挤进全部内容 |
| 数字 | 等宽数字、右对齐、统一精度 | 单位与比较周期紧邻数值 |
| 边界 | 细边框、少量阴影、统一圆角 | 不为每段文字再嵌套卡片 |
| 动效 | 短时状态反馈，不持续闪烁 | 尊重减少动态效果设置 |

至少覆盖已约定的桌面和窄屏视口；未约定时先用 1440×900、1024×768、390×844 作为检查建议，不把它们描述为用户已批准标准。窄屏应重排而不是整体缩放；横向表格可在自身容器滚动，页面不得意外横向溢出。

## 看板布局范式（响应式）

Web 看板默认：页面标题与筛选行、KPI 区、主分析区，采用语义化网格而不是整页卡片堆叠。KPI 数字卡用 Card + `text-3xl font-bold tabular-nums` 大数字 + 同比 Badge，不用图表实现：

```tsx
<section className="grid grid-cols-2 lg:grid-cols-4 gap-4">KPI 卡 ×4</section>
<section className="grid grid-cols-1 lg:grid-cols-3 gap-4">
  <Card className="lg:col-span-2">趋势折线</Card>
  <Card>渠道占比环形</Card>
</section>
<section className="grid grid-cols-1 lg:grid-cols-3 gap-4">
  <Card className="lg:col-span-2">中国地图（下钻）</Card>
  <Card>区域排行条形</Card>
</section>
```

图表高度给在卡片内容区上（如 `h-[300px]`），统一图表组件撑满；flex 布局里放图表必须加 `min-h-0`，否则高度塌陷图表空白。单屏大屏看板另按下方大屏模式组织。

## 大屏模式（16:9 定屏）

用户明确说“大屏／指挥中心／投屏／值守”时采用此模式，与 Web 看板（响应式）分开设计。设计稿固定 1920×1080，外层按视口等比缩放：

```tsx
function useScreenScale() {
  const [scale, setScale] = useState(1)
  useEffect(() => {
    const fit = () => setScale(Math.min(innerWidth / 1920, innerHeight / 1080))
    fit()
    addEventListener('resize', fit)
    return () => removeEventListener('resize', fit)
  }, [])
  return scale
}
// <div style={{ width: 1920, height: 1080, transform: `scale(${scale})`, transformOrigin: 'center top' }} className="dark" />
```

- 根元素强制 `dark`；科技感来自图表配色与少量点缀（如 `shadow-[0_0_24px_hsl(var(--primary)/0.3)]`），不滥用装饰渐变与霓虹。
- 缩放后可读是验收条件：设计稿上文字最小 14px；缩放到 2K 或更小屏后仍应检查是否可读，不以缩放掩盖设计稿过大。
- 2K（2560×1440）与 1080p（1920×1080）都按 16:9 等比放缩即可；低于约定尺寸的窗口应如实说明“大屏按等比缩放”而不是响应式重排。
- 大屏验收仍走单屏无滚动、内容不裁切、下钻原位交互的强制门禁，与 Web 看板一致。

## 令牌与 shadcn 接入

- 使用 background/foreground、card/card-foreground、primary/primary-foreground、muted/muted-foreground、border、input、ring 及 chart-1 至 chart-5 等语义令牌；明暗主题复用名称而不是各写一套组件。
- 为成功、警告、危险、无数据增加语义角色；不要假定增长总为绿色，成本上升等业务必须明确好坏方向。
- shadcn 当前主题文档采用 CSS 变量并展示 OKLCH；旧项目可能使用不同格式，先查变量值和 Tailwind 版本，禁止重复套 hsl()。
- **OKLCH 与 ECharts 兼容坑**：新主题令牌是 `oklch(...)`，zrender（ECharts 底层）对 visualMap 插值、渐变等可能无法可靠解析，轻则色带失效、重则填黑。对策：在 `index.css` 用 hex 覆盖 `--chart-1..5`（明暗各一套），或在图表适配层做 `toSafeColor`（canvas fillStyle 往返转换）防御，转不过来时回退到兜底色板。
- 不强制旧项目切换原语库。所读取的 Chart 文档提供 Radix UI 与 Base UI 入口，接入时必须核实实际生成组件与依赖。
- shadcn 的 Chart 基于 Recharts，不是 ECharts 容器。采用 ECharts 时复用面板、筛选、令牌和信息层级，独立实现 ECharts 适配层，不为视觉一致而安装 Recharts。
- 不把 CSS var(...) 原样视为 Canvas 可解析颜色；按 echarts.md 转换为已验证的颜色值。

## 图表与地图表达

趋势用折线，类别比较用条形，构成仅在少量类别且总量有意义时用饼图，连续强度用顺序色，正负偏离用以零或业务基准为中心的发散色。禁止为了装饰加入无业务意义的 3D、双轴或渐变。

同一实体在图例、图表、地图和表格中保持颜色与名称稳定；分类色与数值渐变不得混用。地图无数据区域使用独立样式与文字说明，不能与最小值同色而无区分。跨层级色阶若重算，必须提示范围变化；需要跨层比较时固定业务色阶。

地图必须有指标、单位、数据时间、图例、层级和返回入口。免责声明不能代替地图许可；来源与审图信息按 china-maps.md 展示。

## 可访问性与状态

- 用原生按钮、表单标签和明确可访问名称；图标按钮必须有名称，悬浮提示不能成为唯一操作说明。
- 支持键盘到达筛选、排序、弹窗、下钻及返回；焦点清晰，弹窗关闭后回到触发元素。
- 普通文本对比度以至少 4.5:1、大文本至少 3:1、关键界面边界至少 3:1 作为项目验收目标，并用实际测量记录验证；这不等于整站已通过无障碍认证。
- 不只靠红绿表达状态；同时使用文字、符号或纹理。图表提供简短结论和可访问数据表，地图提供行政区列表替代入口。
- 加载、空数据、失败、无权限、禁用和过期数据各有明确文案与恢复方式，不允许永久骨架或空白面板。
