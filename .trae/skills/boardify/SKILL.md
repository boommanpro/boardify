# Boardify

按需求确认、工程实现、真实运行验证、证据交付的顺序执行。不要把模板构建成功描述成业务大盘验收通过。

## 固定边界

- 使用 React、Vite、TypeScript、shadcn/ui 和 ECharts。已有项目先检查依赖和约定，不强行覆盖。
- 用 shadcn/ui 的组件与语义设计变量统一风格，不引入其 Chart 示例依赖的 Recharts。
- 交付源码、锁文件、静态构建产物及运行说明。默认通过静态服务器运行，不承诺双击 HTML。
- 模拟数据必须可辨识。不得编造数据来源、指标口径、地图边界、地图许可或验证证据。
- 地图资源在工程内冻结，运行时不依赖第三方边界服务。业务 API 离线能力须另行确认。
- 不自动发布、不提交版本、不覆盖已有目录，不读取或输出密钥。

## 硬性规则（每条都有原因）

1. **未走完强制验证，不得声称“完成”**。静态检查发现不了白屏、空图表、地图 404，必须跑起来看。
2. **地图 GeoJSON 必须本地资源化**，运行时禁止从 CDN 或外网拉取；外网波动即地图空白，且多数交付环境无外网。
3. **adcode 与城市坐标只准来自内置表或 GeoJSON `properties`**，禁止凭记忆编造；错一位数字就 404 或区域错乱。
4. **中国地图必须完整**：含台湾、含南海诸岛（九段线）。按 china-maps.md 识别附属要素并保留，不裁剪、不为“版面干净”过滤。
5. **UI 只用 shadcn/ui + Tailwind**，不混入其他组件库；混库必然样式分裂。
6. **所有图表走统一封装**（resize/dispose/事件/色板已处理）；散落的 `echarts.init` 会造成内存泄漏与 resize 失效。
7. **数据层抽离为唯一数据出口**，mock 与真实数据同构可切换；否则接真实数据时全页面重写。

## 1. 确认需求

读取 [需求规范](references/requirements.md)，复制 [需求记录](assets/templates/requirements.md) 到目标工程文档目录并填实。
优先用选项询问尚未明确的阻塞问题，不重复询问已提供的信息。确认交付形态、数据来源、指标定义、图表、主题、分辨率、刷新与交互、地图范围、网络限制和验收标准。真实数据或地图缺失时先确认是否接受标明来源的演示模式。

区分交付形态：**Web 看板**（响应式，亮暗可切换）与**数据大屏**（16:9 定屏等比缩放，深色，见 [设计系统](references/design-system.md) 的“大屏模式”）。用户说“大屏／指挥中心／投屏／值守”时按大屏处理；单屏看板以目标分辨率无滚动、无裁切为首屏验收条件，两者分开设计，不混用。

## 2. 建立工程

读取 [工程规范](references/engineering.md) 和 [设计系统](references/design-system.md)。新项目使用 [起始工程](assets/starter)，不要从零重写基础设施。

从本技能所在目录执行，目标为新的空目录：

```sh
node scripts/init.mjs /absolute/path/to/dashboard
```

进入目标目录后执行：

```sh
npm ci
npm run dev
```

已有项目只选择性迁移适配后的组件，保留原有配置与用户修改。模板示例不是默认业务需求；依据需求替换指标、数据适配及布局。

## 3. 实现图表和地图

读取 [ECharts 规范](references/echarts.md)。沿用模板图表容器，保持尺寸观察、主题重建、事件解绑及销毁；给关键指标提供可访问的数据替代，不以 Canvas 元素存在作为图表正确的证据。

涉及地图必须读取 [中国地图规范](references/china-maps.md)。先建立来源、许可、版本、坐标系、哈希与层级清单，再接入几何和业务数据。模板只有明确标记的三级合成 Polygon 示例，不包含真实中国地图，不证明真实行政区覆盖能力。

地图规范内置防乱答知识：DataV GeoAtlas 实测事实（35 要素含九段线、`childrenNum` 行为、东莞／中山／台湾 404 属预期）、34 省级 adcode 权威表、常用城市坐标参考表，以及下钻交互实测坑（geo 组件点击不触发、打点拦截点击、不双画叠层）。参考值只在接入工程后以实际资产 `properties` 为准核对，禁止把参考表直接当作当前版本事实。

真实中国区域常含 MultiPolygon。接入前扩展运行时校验器、类型与测试，禁止丢弃岛屿或强转 Polygon。行政区代码按字符串保存；未知子级不生成边界。资源覆盖不足时禁用对应下钻并说明原因。

真实业务接入前读取 [电商示例实践](references/ecommerce.md)。仓库 `examples/ecommerce` 是独立本地学习示例，不是获准公开发布的地图包。采集脚本必须显式指定目标目录及 `--learning-only`，不得覆盖 starter；该参数只声明用途，不产生授权。源属性码与 series.name 均须统一为字符串，并验证色阶及真实图形点击，不能只验收行政区按钮。

## 4. 强制验证

先读取 [交付验证规范](references/delivery-validation.md)，再执行检查，不得在结束时才补验收。

在本技能目录执行模板完整性检查：

```sh
node scripts/validate.mjs
node scripts/verify.mjs
```

两个检查器的地图哈希基线只适用于未经替换的模板及其副本。真实业务工程替换资产后，应建立经核对的业务资产清单与校验器，不能更新哈希掩盖未知修改，也不能把模板检查结果用于业务验收。

目标工程至少执行：

```sh
npm test
npm run build
npm run preview
```

构建包含 TypeScript 检查；模板尚无独立 lint 命令，不声称 lint 已通过。需要静态规范检查时补充配置并实际执行。

生产预览启动成功后，使用可用浏览器能力验证可见图表、真实点击、键盘、主题、视口、下钻和返回，核查控制台与网络。地图冷启动需允许本地服务且阻断外网；不得用断开本地服务来代替该测试。无浏览器能力时记录受阻，不以单元测试替代真实渲染。

## 5. 交付

复制并填写 [验收记录](assets/templates/acceptance.md)，逐项关联证据与版本。使用 [交付清单](assets/templates/handoff.md) 核对产物。
所有适用强制门禁通过才写“已完成并验证”；否则列出通过、失败、受阻及不适用项目和解除条件。保留构建体积警告、数据范围与地图覆盖限制，不隐藏它们。
